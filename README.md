# Архитектура ИС оценки битых автомобилей (Техническое задание для разработки)

## Общие сведения и принципы

**Назначение:** Автоматизация процесса оценки остаточной стоимости битых автомобилей для компаний-скупщиков. Система рассчитывает потенциальную выручку от продажи уцелевших запчастей и формирует рекомендацию по цене выкупа.

**Ключевые архитектурные принципы:**

1. **Асинхронность:** Оценка — фоновая задача (Celery), так как парсинг сайтов и работа AI-модуля занимают время. Клиент получает статус и результат по API.
2. **Модульный монолит:** Backend (FastAPI) — единая точка входа и оркестратор. Тяжёлые модули (AI, парсер) вынесены в отдельные воркеры.
3. **Мультимодальность AI:** Модель анализирует **фото + текстовое описание повреждений + пробег + данные автомобиля**. Текст помогает там, где фото неинформативно (тень, грязь, ракурс), а комбинация модальностей повышает точность.
4. **Встроенная объяснимость (intrinsic explainability):** Объяснение — это **прямой выход модели**, а не генерация отдельной LLM. Используются SHAP-значения, attention-карты (на какие области фото смотрела модель) и token-level importance (какие слова в описании повлияли). Механик видит не только «что решила модель», но и «почему».
5. **Прозрачность цен:** Каждая цена сопровождается ссылкой на источник объявления.
6. **Безопасность внешних данных:** Frontend общается только с Backend. Backend инкапсулирует доступ к внешним сайтам (Авито, Авто.ру) и AI-моделям.
7. **Человеко-ориентированность:** Система выдаёт рекомендацию, финальное решение о цене принимает механик.

## Системные требования

**Требования к системе в целом:**
*   Система должна обеспечивать круглосуточный доступ (99.9%).
*   Система должна поддерживать ролевую модель (Руководитель, Механик, Старший механик (опционально), Наблюдатель).

**Требования к функциям:**
*   Приём фото (до 20 шт.) и текстового описания повреждений.
*   Опциональное определение авто по VIN.
*   Выдача списка деталей с оценкой пригодности (уверенность ИИ, обоснование в виде факторов).
*   Сбор цен с Авито и Авто.ру, расчёт медианы.
*   Расчёт итоговой стоимости: Сумма медиан − стоимость разборки.
*   Формирование JSON-отчёта (без истории снимков, только даты получения).
*   Ежедневный мониторинг цен и генерация рекомендаций.

**Требования к надёжности и безопасности:**
*   Доступ по JWT-токенам.
*   Хранение данных в соответствии с настраиваемым сроком (1/7/30 дней).
*   Защита от парсинг-блокировок (rate limits, прокси).

**Требования к прозрачности (Explainable AI):**
*   Каждая цена должна сопровождаться ссылкой на источник.
*   ИИ должен возвращать факторы, повлиявшие на решение (пробег, зона удара, текстовое описание).

## Компоненты и стек технологий

```text
[React SPA] 
     │ (REST API)
     ▼
[Nginx / API Gateway]
     │
     ▼
[Backend API — FastAPI/Python] ──── [PostgreSQL 16]
     │      │      │                [S3/MinIO (Фото, Attention Maps)]
     │      │      └── [Redis + Celery (Очередь задач)]
     │      └── [Calculator Module] (Синхронный расчёт)
     ▼
[Celery Workers]:
  ├── AI Worker (мультимодальная модель: image + text + structured)
  ├── Parser Worker (Авито, Авто.ру)
  ├── Monitoring Worker (Ежедневный пересчёт)
  └── Retention Worker (Очистка данных)
```

| Компонент | Стек | Назначение |
| :--- | :--- | :--- |
| **Frontend** | React 18+, TypeScript, Vite | SPA с интерактивной таблицей, загрузкой фото, визуализацией объяснений, JSON-экспортом. |
| **Backend API** | Python 3.11+, FastAPI, Uvicorn | Аутентификация, RBAC, оркестрация, REST API. |
| **Очередь** | Celery 5+, Redis 7 | Асинхронная обработка тяжёлых задач (AI, парсинг). |
| **AI Worker** | Python, PyTorch, HuggingFace Transformers, SHAP | **Мультимодальная модель**: image encoder (ViT/ResNet) + text encoder (RuBERT) + fusion layer. Возвращает `suitability`, `confidence`, `factors[]` с `source`, `attention_map_url`. |
| **Parser Worker** | Python, HTTPX / Playwright | Сбор актуальных цен с Авито и Авто.ру. |
| **База данных** | PostgreSQL 16 | Метаданные, оценки, офферы, аудит, справочники. |
| **Хранилище** | S3-совместимое (MinIO) | Фото автомобилей и attention-карты (с автоудалением по TTL). |
| **Инфраструктура** | Docker, Docker Compose, Nginx | Контейнеризация, API Gateway, SSL. |

## AI-модуль: мультимодальная модель и встроенная объяснимость

### Входные данные

```text
Вход:
  ├── Фото (до 20 шт.)
  ├── Текстовое описание повреждений (от механика)
  ├── Пробег
  └── Данные авто (make, model, year, engine)
```

### Архитектура модели

```text
     ┌──────────────────────────────┐
     │   Мультимодальная модель     │
     │                              │
     │  Image Encoder (ViT/ResNet)  │
     │  Text Encoder (RuBERT)       │
     │         │         │          │
     │         └────┬────┘          │
     │              ▼               │
     │     Fusion Layer             │
     │  (concat / cross-attention)  │
     │              │               │
     │              ▼               │
     │   Выход: список деталей      │
     │   + suitability + confidence │
     │   + factors[] с source       │
     │   + attention_map_url        │
     └──────────────────────────────┘
```

### Встроенная объяснимость

| Метод | Что объясняет | Источник |
| :--- | :--- | :--- |
| **SHAP** | Вклад каждого признака (пробег, зона удара, тип детали, совпадение с текстом) в итоговый прогноз | Вычисляется на выходе модели |
| **Attention maps** | На какие области фото модель смотрела при решении | Из слоёв внимания ViT/CNN; сохраняется как изображение в S3 |
| **Token-level importance** | Какие слова в описании повлияли на решение | Из слоёв внимания текстового энкодера |
| **Rule attribution** | Сработало ли правило износа (например, «АКПП после 100 тыс. км») | Из модуля правил |

### Формат выхода AI-модуля

```json
{
  "part": "Дверь передняя левая",
  "suitability": "not_usable",
  "confidence": 0.91,
  "factors": [
    {
      "name": "image_damage_zone",
      "value": "front_left_door_deformation",
      "impact": "negative",
      "weight": 0.52,
      "source": "image"
    },
    {
      "name": "text_description_match",
      "value": "удар в переднее левое крыло",
      "impact": "negative",
      "weight": 0.28,
      "source": "text"
    },
    {
      "name": "mileage",
      "value": 98000,
      "impact": "neutral",
      "weight": 0.10,
      "source": "structured"
    },
    {
      "name": "model_wear_rule",
      "value": "door_no_critical_wear",
      "impact": "neutral",
      "weight": 0.10,
      "source": "rule"
    }
  ],
  "attention_map_url": "https://s3.../attention_door_left.png",
  "key_tokens": ["удар", "разрушена", "переднее левое"]
}
```

### Что видит механик в интерфейсе

```text
Деталь: Дверь передняя левая
Решение: Не пригодна (уверенность 91%)

Почему:
  🔴 Фото: деформация в зоне передней левой двери (вклад 52%)
  🔴 Текст: «удар в переднее левое крыло» (вклад 28%)
  ⚪ Пробег: 98 000 км — в норме для этой детали (вклад 10%)
  ⚪ Правило износа: не сработало (вклад 10%)

[Показать тепловую карту внимания на фото]
```

**Тепловая карта** — наложение на исходное фото, где красным выделены области, на которые модель смотрела сильнее всего. Механик может согласиться или не согласиться с решением, видя его основания.

## Роли и права доступа (RBAC)

| Роль | Описание | Права |
| :--- | :--- | :--- |
| **`head`** (Руководитель) | Владелец компании или директор | Управление пользователями и настройками (срок хранения, регион по умолчанию). Просмотр всей статистики и оценок. Управление источниками цен. |
| **`mechanic`** (Механик/Оценщик) | Основной пользователь | Создание оценок (загрузка фото, VIN, описание). Редактирование предложенных деталей, ввод стоимости разборки. Экспорт JSON. |
| **`senior_mechanic`** (Старший механик) | Бригадир смены (опционально) | Все права `mechanic` + просмотр и корректировка оценок других механиков своей смены. |
| **`observer`** (Наблюдатель) | Партнёр или аудитор | Только чтение оценок и статистики (без права изменения данных). |

## Бизнес-логика и расчёт

**Основная формула:**
`Рекомендуемая стоимость = Σ (Медианных цен пригодных деталей) − Стоимость работ по разборке`
*(Маржа компании в формулу не закладывается, она обсуждается на этапе торга).*

**Правила формирования цен (Fallback):**
*   **Порог достаточности:** минимум **3** валидных объявления с Авито/Авто.ру.
*   **≥ 3 объявлений:** берётся медиана, флаг `ok`. Включается в итог.
*   **1–2 объявления:** берётся медиана, флаг `low_data_confidence`. По умолчанию **не включается** в итог до подтверждения механиком.
*   **0 объявлений:** справочная цена (Каталожная цена × КЛН). Флаг `no_market_price`. **Не включается** в итог автоматически.

**Учёт ресурса деталей:** AI-модель сверяет пробег с правилами износа (например, АКПП для конкретной модели требует замены после 100 тыс. км). Если правило срабатывает — деталь помечается как непригодная, а правило появляется в `factors[]` с `source: "rule"`.

## Схема данных

*   **`companies`**: `id`, `name`, `retention_days` (1/7/30), `default_region` (по умолчанию "Екатеринбург").
*   **`users`**: `id`, `company_id`, `role`, `email`, `password_hash`.
*   **`vehicles`**: `id`, `vin` (nullable), `make`, `model`, `year`, `source` (vin/photo/manual).
*   **`assessments`**: `id`, `company_id`, `user_id`, `vehicle_id`, `status` (queued/processing/calculated/failed), `region`, `mileage`, `damage_description`, `disassembly_cost`, `recommended_total`.
*   **`assessment_items`** (Детали): `id`, `assessment_id`, `part_name`, `suitability` (usable/conditionally/not_usable), `ai_confidence`, `ai_factors` (JSONB), `ai_attention_map_url`, `ai_key_tokens` (JSONB), `median_price`, `offers_count`, `data_quality_flag`, `included_in_total` (bool).
*   **`price_offers`**: `id`, `assessment_item_id`, `source` (avito/autoru), `price`, `url`, `published_at`, `fetched_at`.
*   **`kls_coefficients`**: `id`, `part_group`, `coefficient` (справочник коэффициентов ликвидности для fallback).
*   **`wear_rules`**: `id`, `make`, `model`, `part_group`, `mileage_threshold` (правила износа, на которые ссылается AI-модуль).
*   **`audit_log`**: Логирование всех действий пользователей.

## Ключевые Endpoints API

| Метод | Endpoint | Описание |
| :--- | :--- | :--- |
| `POST` | `/api/v1/auth/login` | Получение JWT. |
| `POST` | `/api/v1/assessments` | Создание оценки (multipart/form-data: фото, VIN, пробег, описание). Возвращает `assessment_id` и статус `queued`. |
| `GET` | `/api/v1/assessments/{id}/status` | Polling статуса обработки (catalog → ai → parser → calculated). |
| `GET` | `/api/v1/assessments/{id}` | Получение полного результата (таблица деталей, расчёт, объяснения). |
| `PATCH` | `/api/v1/assessments/{id}/items` | Ручная корректировка (включить/исключить деталь, переопределить цену). |
| `GET` | `/api/v1/assessments/{id}/export` | Выгрузка в JSON (schema 1.1). |
| `GET` | `/api/v1/assessments/{id}/items/{item_id}/attention-map` | Получение attention-карты (изображение) для визуализации. |
| `GET` | `/api/v1/monitoring/recommendations` | Список рекомендаций по изменению цен (для Head). |
